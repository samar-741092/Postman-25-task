# Analysis of Dense vs. Sparse Attention Mechanisms

## 1. Information Loss Across Sparsity Patterns

* **Sliding Window (Local) Pattern**:
  * Only looks at nearby tokens within a set window $w$.
  * For information to reach distant tokens, it must step incrementally through $O(N/w)$ layers, creating a context bottleneck over long sequences.

* **Random Pattern**:
  * Randomly connects distant keys to approximate small-world network connectivity.
  * While it speeds up information flow across the sequence, it removes the clear structural patterns needed for precise grammar and syntax.

* **Global Pattern**:
  * Funnels sequence context into a small set of dedicated global tokens.
  * It keeps long-range connections intact, but loses fine-grained details between non-global distant tokens.

## 2. Structural Role of Global Tokens

Global tokens play a critical role in sparse attention due to two structural advantages:

* **Shortcut Connections**: They act as a central hub. Token A can share data with Token B in just one step ($\text{Token A} \to \text{Global Token} \to \text{Token B}$) instead of stepping through multiple layers.

* **Context Broadcasting**: They gather state information from the whole sequence and broadcast it to every query at once. This protects long-term memory without heavy computational overhead ($O(g \cdot N)$, where $g$ is the number of global tokens).

## 3. Why Sparse Attention Underperformed in Benchmarks

When run as a dense simulation with standard matrix operations, **sparse attention can exhibit higher execution latency and equal peak memory allocation compared to causal dense attention**.

### Main Causes:

1. **Full Memory Allocation**: Simulating sparse attention on dense matrix functions still allocates the full $O(N^2)$ memory footprint for raw dot-product scores ($QK^T$).

2. **Computational Latency**: The GPU performs the complete $O(N^2)$ matrix multiplication first, then spends extra execution time applying a boolean masking operation across all elements.

### Hardware Realization

To achieve actual speed and memory savings, sparse attention requires custom GPU kernels (such as FlashAttention mask-skipping or Triton block-sparse operators) that skip calculating zeroed-out blocks entirely, rather than masking a full matrix after computing it.
